# Development contract — 0.1.0

This contract is deliberately narrower than SMTP or MIME in general. Numeric limits are fixed in this version. The supported execution environment is unprivileged Ruby 3.4 on Linux, a local filesystem with flock, atomic same-filesystem directory rename and fsync support, and a trusted parent directory. No network peer other than local test clients is intended.

## SMTP endpoint and states

The only listener address is numeric `127.0.0.1`. Port is 0–65535; 0 requests an ephemeral port. The application never uses an envelope domain for networking, never relays and has no outbound-delivery code. EHLO advertises exactly `SIZE 262144`, not AUTH, STARTTLS, SMTPUTF8 or 8BITMIME.

States are ungreeted, greeted/empty, sender, and sender-with-recipients. Successful EHLO/HELO clears the transaction, retains the session and enters greeted/empty. MAIL requires a greeting; successful MAIL replaces the current transaction. RCPT requires a sender. DATA requires a sender and at least one accepted RCPT. Rejected RCPT preserves all accepted RCPTs. RSET clears sender, recipients and transaction deadline, not the greeting. NOOP and QUIT do not require a transaction. RSET/NOOP/DATA/QUIT take no arguments. Unknown verbs return 502. Command names and FROM/TO/SIZE keywords are case-insensitive; addresses are not case-folded.

MAIL syntax is `MAIL FROM:<address>` with optional ` SIZE=decimal`. The empty reverse-path `<>` is supported and stored as an empty string. SIZE is a bounded decimal admission hint, not an exact-size promise. RCPT syntax is `RCPT TO:<address>` without parameters. ASCII addresses are at most 254 bytes; local parts at most 64, comprising nonempty dot-separated runs of letters, digits, underscore, plus or hyphen. Domains have at least two labels of 1–63 lowercase ASCII letters/digits/hyphens, without edge hyphens. Quoted local parts, comments, address literals and non-ASCII are unsupported. Sender domains are syntax only; recipients must end in the exact domain `example.test`. Local-part case is preserved. Duplicate accepted RCPT commands are retained and count toward 16.

Replies: 220 greeting, 250 successful command/acceptance, 354 DATA invitation, 221 QUIT, 500 framing/command syntax, 501 argument/address syntax, 502 unsupported command, 503 sequencing, 550 recipient domain rejection, 552 size/header limit, 554 invalid DATA encoding/header syntax, 452 capacity and 421 deadline/session admission. Ordinary syntax/sequencing/rejection replies keep the session. A failed DATA admission returns 452 before 354, clears the transaction and keeps the session. Fatal errors during DATA, framing, time or command-count violations close immediately after a best-effort error reply. There is no drain mode. OS I/O failure can instead cause immediate EOF.

## Wire and time bounds

CRLF is mandatory. Bare LF, embedded bare CR and NUL/non-ASCII DATA are rejected. Command lines include CRLF and are at most 512 bytes. DATA lines include CRLF and are at most 1000 bytes **before** dot removal. `.<CRLF>` terminates DATA; one leading dot is removed from every other dot-prefixed line. Raw size is the sum of resulting bytes, including CRLF, not SMTP terminator or removed dots, at most 262144. DATA wire bytes including terminator are separately capped at 524291. Total received bytes per session are capped at 1 MiB. A reader buffers at most the current line bound plus one byte.

There are at most four owned sessions and 100 commands per session. A fifth gets best-effort 421 and closes. Absolute monotonic session lifetime is five seconds. Successful MAIL starts a two-second absolute transaction deadline; input trickles do not extend it. Input idle allowance is one second. RSET cannot extend the session deadline. Deadlines govern user-space socket waits/checkpoints, not an indefinitely stalled kernel/filesystem. Deliberately enabled fault gates pause publication for crash testing and are the sole intentional deadline exception.

Top-level DATA requires a header/body blank separator. Header limits: 64 fields, 4096 bytes per field including continuation lines, 16384 bytes across field lines; DATA line bounds still apply. Header field names are printable ASCII excluding colon. Invalid continuation/header syntax is fatal.

## Storage and visibility

The caller supplies a new or recognized private mailbox, leaf mode 0700, owned by the current UID. Files are mode 0600, owned regular single-link files; symlinks are not followed. Parent directories must be trusted. This is not protection against another process running as the same UID with filesystem access.

`.owner.lock` is held exclusively and nonblocking for the sink lifetime. `.mailbox.lock` plus an in-process mutex serializes reservations, writes, commits and cleanup. Readers use shared locking. Each DATA admission reserves one slot and its complete immutable JSON envelope plus ownership marker **before writing**. Every append reserves bytes before writing. Global reservations cover committed plus all in-flight stages. The maximum is 100 committed-plus-staged slots, four stages and 16777216 logical payload bytes. Payload includes `.owned`, `envelope.json` and `message.eml`, not filesystem block overhead, directory entries, empty lock files, journal space or kernel buffers. Failed writes remain reserved until stage cleanup. Raw stage size is also enforced in the storage API.

A stage has an unpredictable `stage-` name and three fixed files. Raw bytes and JSON metadata are synced; publication is one directory rename to `delivery-NNNNNN` on the same filesystem under exclusive lock. IDs begin at 000001 and are allocated serially from contiguous committed state only at publication. No deduplication, deletion API, compaction or ID reuse after committed delivery is supported. Failed staging does not consume IDs. The published directory and root are synced before final `250 stored NNNNNN`. A reader exposes only delivery directories, never stages.

Restart validates bounded entries and committed metadata before serving. At most four recognized owned orphan stages are validated and removed. Unknown files, malformed stages, symlinks, excessive entries, missing ownership marker or noncontiguous deliveries cause startup failure, not recursive deletion. A crash in the tiny mkdir-to-marker interval can leave an unrecognized stage requiring manual review. There is no arbitrary-path cleanup. These are process-crash semantics; no power-loss or hardware durability guarantee is made. Publication followed by disconnect before 250 is uncertain delivery and retry may produce a duplicate.

## Reader and inspector

`MailboxReader.new(path).list` returns an array sorted by ID. Each element has `id` (six decimal digits), `envelope` (`version: 1`, `mail_from`, `rcpt_to`) and `raw_bytes`. `read(id)` adds binary `raw`. Invalid IDs, foreign metadata/files and absent deliveries raise `CaptureLab::Error` with a stable `code`; JSON metadata is size- and nesting-limited and validated as untrusted input. Inspection never trusts metadata for filenames or raw sizes.

`Inspector.raw(binary_string)` returns JSON-compatible data. `Inspector.delivery(path, id)` returns reader metadata plus `inspection`. On success: `ok: true`, ordered `texts`, ordered `attachments`, `decoded_bytes`, `attachment_bytes`, `diagnostics`. Each text has `content_type`, pre-normalization `decoded_bytes`, and UTF-8 `text`; CRLF is normalized to LF, bare CR rejected. Each attachment has nullable `name`, `content_type`, `decoded_bytes`, lowercase `sha256` and lowercase `hex`. Names are data, including slashes and dot segments, never filesystem destinations. A named part, attachment disposition, or non-text leaf is an attachment. Multipart containers contribute no decoded bytes.

Raw inspection input is separately bounded to 256 KiB, ASCII/CRLF lines of at most 1000 bytes and top-level header limits before Mail.new. MIME parsing uses mail 2.9.1 in one owned worker process. Direct parts are walked iteratively; root depth is zero, maximum depth eight, at most 64 visited/queued parts including containers. Depth is checked before descending; direct child count is checked after accessing `parts`, before scheduling children. Header limits apply to each part's serialized fields after parsing. Aggregate decoded leaf bytes are at most 256 KiB, independently of encoded/raw size. Filenames are UTF-8 data, at most 1024 bytes.

**These are inspection traversal bounds, not a structural MIME preflight or a guarantee that no mail parser expansion occurs first.** Mail.new, header access, multipart predicates and direct `parts` access may perform internal work before a guard. `diagnostics.mail_body_splits` instruments the actual Mail::Body#split! expansion path, including expansion preceding our traversal checks. Raw/input bounds, isolated process memory/CPU bounds and the parent deadline cover this remaining risk; they do not prove parser safety.

Supported leaf encodings: default/explicit 7bit, strict canonical base64 with only CRLF folding, and quoted-printable with every equals followed by two hex digits or CRLF. Transfer decoding uses mail; base64 is independently strictly validated and compared. Text charsets: US-ASCII and UTF-8 with valid bytes, no replacement. `message/*`, unknown transfer encodings/charsets, encoded-word headers detected in field values and RFC2231 extended filename/name parameters are rejected. This is not all of MIME. Multipart preambles/epilogues are not returned.

Errors return `ok: false`, `error`, optionally `diagnostics`, with no texts/attachments. Codes include `raw_limit`, `crlf_required`, `line_limit`, `wire_encoding`, `header_separator`, `header_syntax`, `header_continuation`, `header_limit`, `mime_depth`, `mime_parts`, `mime_empty`, `nested_message`, `decoded_limit`, `charset`, `text_encoding`, `text_newline`, `transfer_encoding`, `encoded_header`, `attachment_name`, `mime_invalid`, `worker_timeout`, `worker_output`, `worker_failed`, `worker_protocol`. A resource-killed parser yields worker_failed, not an invented semantic diagnosis.

The parent permits three seconds absolute wall time and at most 2 MiB stdout/16 KiB stderr. Worker spawn sets RLIMIT_AS=384 MiB, CPU=2 seconds, CORE=0 and NOFILE=32 where available. All exit paths terminate the owned process group if necessary and wait for the child. The supported Linux environment provides these limits; other platforms are not promised equivalent containment. Direct invocation of internal `bin/decode.rb` is not the constrained public inspector interface.

## CLI and subprocess scenarios

Sink stdout contains only bounded ready/fault JSON events; errors are JSON on stderr with nonzero exit. Inspect without ID lists; with ID inspects, and `--json` emits JSON. Inspection failure exits 1; success exits 0. Usage/storage failures use JSON `ok: false` and nonzero exit. No attachment execution or extraction occurs. Human inspector output JSON-escapes untrusted strings.

Demo and integration tests own private temporary namespaces and child processes, with a 20-second scenario deadline, bounded output, process-group termination and reaping. The sending client is the independent net-smtp gem with STARTTLS explicitly disabled, numeric loopback and fixed synthetic recipients. Date is `Thu, 01 Jan 2026 00:00:00 +0000`; Message-ID is `<fixture-001@example.test>`. MIME bytes are supplied directly, not generated by mail. JSON output is deterministic in content; object key order is not a consumer contract.
